## Narrow vs wide

* **Narrow** (map, filter, flatMap, mapValues, coalesce): each child partition depends on one parent partition, so Spark pipelines the whole chain inside one task; no data moves.
* **Wide** (join, reduceByKey, groupByKey, repartition): a child partition needs data from many parents, so Spark writes shuffle files and starts a new stage. The two inputs of the join are two ShuffleMapStages; the post-join reduceByKey is another; `collect` runs the ResultStage.
* The small-files effect: `textFile` creates one partition per 15-minute snapshot file, which is why the pipeline coalesces before heavy work.
